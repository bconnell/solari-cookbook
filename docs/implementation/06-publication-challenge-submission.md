# ReproDocket Publication and Challenge Submission Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a truthful, polished ReproDocket presentation inside the public Solari cookbook fork only after the exact candidate has passed engineering, hardening, and human acceptance gates, then prepare a concise challenge demonstration and social submission that follows the published instructions.

**Architecture:** Publication is a projection of validated product truth, not a separate marketing reality. The root cookbook remains recognizable, ReproDocket gets a focused project README, documentation links point to current supported behavior, and demo evidence is generated by the same real user path that was validated.

**Tech Stack:** Git/GitHub, Markdown, existing ReproDocket build/validation scripts, real Solari runtime evidence.

**Spec:** `docs/reprodocket-design.md`; plans 1-5; validation output from the exact release candidate.

## Global Constraints

* Do not begin final publication wording until Plan 5's final Full validation and human QA are complete for the same release candidate.
* Preserve the fork relationship, upstream Solari examples, and root MIT license/copyright.
* Do not claim autonomous arbitrary-site bug discovery unless a runtime planner was actually implemented and validated.
* Do not call a feature Available/complete from a class, route, screenshot, or partial test alone.
* No real API key, credential, private local path, account identifier, or sensitive target evidence may enter tracked/public files.
* Demonstration media must come from the real current product path, not a separately mocked UI.
* Any final code/doc change after validation invalidates the affected validation evidence and may require a new Full run.
* The final social post is not published automatically. User approval remains the final public-mutation boundary.
